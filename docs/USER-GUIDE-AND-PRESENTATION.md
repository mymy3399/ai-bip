# AI-BIP Police AI Platform

## คู่มือการใช้งานและแนวทางจัดทำเอกสาร/วิดีโอนำเสนอ

เอกสารนี้สรุปหลักการทำงาน วิธีสาธิต และข้อควรระวังของต้นแบบ AI-BIP เพื่อใช้เป็นต้นฉบับสำหรับคู่มือผู้ใช้ เอกสารอบรม สไลด์ และวิดีโอแนะนำระบบ

## 1. หลักการของระบบ

AI-BIP เป็นระบบช่วยจัดระเบียบข้อมูลและสนับสนุนการวิเคราะห์สำหรับเจ้าหน้าที่ตำรวจ ไม่ใช่ระบบยืนยันตัวบุคคล ไม่ใช่ระบบตัดสินความผิด และไม่ใช่ระบบออกคำสั่งจับกุม

หลักการสำคัญ:

- Human-in-the-Loop: เจ้าหน้าที่ต้องตรวจสอบผลทุกครั้งก่อนดำเนินการ
- Screening First: ผล Field Check เป็นการคัดกรองเบื้องต้นเท่านั้น
- Explainable Output: แสดงเหตุผล ข้อมูลสนับสนุน ข้อมูลที่ยังขาด และแหล่งอ้างอิง
- Case Context: ผลกฎหมาย แนวคำพิพากษา Bail Risk และ Statute Reference เปลี่ยนตามคดีที่เลือก
- Mobile First: หน้าภาคสนามและเมนูสำคัญต้องใช้งานบนมือถือได้
- Synthetic by Default: ข้อมูล ภาพบุคคล เลขประชาชน และข้อมูลทะเบียนในต้นแบบเป็นข้อมูลจำลอง

## 2. โมดูลและวิธีใช้งาน

### 2.1 Biometric Field Check

ใช้คัดกรองบุคคลจากข้อมูลที่เจ้าหน้าที่มี โดยเลือกวิธีเดียวหรือหลายวิธีร่วมกัน:

1. เลือก Fingerprint, Face หรือ ID Card
2. ID Card รองรับชื่อและเลขประชาชน เลือกกรอกอย่างใดอย่างหนึ่งหรือทั้งสองอย่างได้
3. Face และ Fingerprint แสดงขั้นตอน Capture/Scan พร้อมแอนิเมชัน
4. หากใช้ภาพและลายนิ้วมือพร้อมกัน ระบบจำลองการค้นหาแบบ Multi-modal
5. กดค้นหาและรอผลคัดกรอง
6. หน้า Candidate List แสดงชื่อและเลขประชาชนจำลองของผู้สมัคร
7. การค้นด้วย ID Card อย่างเดียวเป็น 1:1 จึงไม่แสดงคะแนนความใกล้เคียง
8. การค้นด้วย Face/Fingerprint อาจแสดง similarity เพื่อจัดลำดับเท่านั้น ไม่ใช่การยืนยัน
9. เปิดรายละเอียด Candidate เพื่อดูแหล่งข้อมูลและประเด็นที่ต้องตรวจต่อ

ข้อความกำกับที่ต้องคงไว้:

> ข้อมูลนี้เป็นผลคัดกรองเบื้องต้น ไม่ใช่การยืนยันตัวบุคคลหรือสถานะทางคดี

### 2.2 ANPR Surveillance Center

แท็บหลักมี 3 แท็บ:

- เฝ้าระวัง Real-time
- ทะเบียนเฝ้าระวัง
- ตรวจข้อมูลกรมขนส่ง

ภายในแท็บเฝ้าระวัง Real-time มีแท็บย่อย:

- ภาพสดกล้องวงจรปิด ANPR Stream
- แผนที่ปิดล้อมเรียลไทม์และสั่งการสายตรวจ (Geofence Map)

การจัดการทะเบียนเฝ้าระวัง:

1. เปิดแท็บทะเบียนเฝ้าระวัง
2. กรอกเลขทะเบียน จังหวัด ประเภท และรายละเอียด
3. เลือกประเภท หมายจับ รถหาย หรือเฝ้าระวังอื่น ๆ
4. กดบันทึกทะเบียน
5. ตรวจรายการที่บันทึกและสถานะบนหน้าจอ

การตรวจข้อมูลทะเบียน:

1. เปิดแท็บตรวจข้อมูลกรมขนส่ง
2. กรอกเลขทะเบียน หรือถ่ายภาพ/อัปโหลดภาพป้ายทะเบียน
3. กดตรวจสอบข้อมูลทะเบียน
4. อ่านผลผู้ครอบครอง รุ่นรถ จังหวัด และสถานะเฝ้าระวัง

ในต้นแบบ ผลตรวจกรมการขนส่งและการสกัดเลขทะเบียนเป็นข้อมูลจำลอง การเชื่อมต่อจริงต้องใช้ API ที่ได้รับอนุญาตและมีระบบสิทธิ์/บันทึกการใช้งาน

### 2.3 Legal AI / Fact Analyzer

1. เปิดแท็บวิเคราะห์คดี
2. เลือก Preset คดี หรือเขียนพฤติการณ์เอง
3. กดวิเคราะห์พฤติการณ์คดี
4. รอแอนิเมชันการค้นหาและจัดอันดับฐานความผิด
5. ตรวจ Fact Matrix ว่าองค์ประกอบใดพบแล้วและองค์ประกอบใดยังขาด
6. ตรวจ Candidate Charges และเลือกฐานความผิดเพื่อดูรายละเอียด
7. เปิดแท็บแนวคำพิพากษาเพื่อดูคดีที่เทียบเคียงกับคดีปัจจุบัน
8. เปิดแท็บ Bail Risk เพื่อดูคะแนน ปัจจัย และคำแนะนำที่เปลี่ยนตามคดี
9. เปิด Statute Reference เพื่อดูมาตราที่เกี่ยวข้องกับคดีปัจจุบันก่อน และยังค้นกฎหมายทั้งหมดได้
10. ใช้การร่างบันทึก/คำร้องเป็นต้นฉบับช่วยงาน แล้วตรวจเอกสารฉบับใช้บังคับก่อนนำไปใช้

Preset ที่มีในต้นแบบ:

- ลักทรัพย์ในเวลากลางคืน
- ฉ้อโกงประชาชนผ่านระบบคอมพิวเตอร์
- ทำร้ายร่างกายชิงทรัพย์

### 2.4 Police AI Assistants

1. เลือกผู้ช่วยตามภารกิจจากแท็บย่อย
2. เลือก Prompt ตัวอย่างหรือพิมพ์คำถาม
3. อ่านคำตอบและแหล่งอ้างอิง
4. ตรวจวันที่และฉบับเอกสารก่อนนำคำตอบไปใช้

ผู้ช่วยในต้นแบบประกอบด้วย Investigator, Personnel/HR และ Procurement

### 2.5 Operational Flow / Presentation Mode

ใช้แสดงลำดับการทำงานตั้งแต่ Field Screening, Human Review, Formal Verification ไปจนถึง Investigation และ Candidate Review เหมาะสำหรับประชุมหรืออธิบายภาพรวมแก่ผู้บริหาร

## 3. วิธีรับมือผลลัพธ์

| ผลที่เห็น | ความหมาย | สิ่งที่ต้องทำต่อ |
|---|---|---|
| Candidate หลายรายการ | มีผู้สมัครที่อาจสอดคล้องหลายราย | เปรียบเทียบข้อมูลและเปิดรายละเอียด |
| Similarity สูง | ใช้จัดลำดับผลชีวมิติ | ห้ามถือเป็นการยืนยันตัวบุคคล |
| พบข้อมูลที่อาจเกี่ยวข้องกับหมายจับ | พบข้อมูลจำลองที่ต้องตรวจซ้ำ | ตรวจระบบหลักและปฏิบัติตามขั้นตอน |
| Fact Matrix มีรายการ pending | หลักฐานหรือองค์ประกอบยังไม่ครบ | สอบสวน/ขอข้อมูลเพิ่ม |
| Bail Risk สูง | ปัจจัยจำลองมีความเสี่ยงสูง | ใช้ประกอบดุลพินิจ ไม่ใช่คำสั่งอัตโนมัติ |

## 4. ข้อมูลจำลองและสิ่งที่ยังไม่เชื่อมต่อ

ต้นแบบยังไม่เชื่อมต่อ:

- AFIS หลักหรือเครื่องอ่านลายนิ้วมือจริง
- ฐานทะเบียนราษฎร์/ตำรวจ/หมายจับจริง
- กรมการขนส่งจริง
- ระบบบัญชีธนาคาร IP Log หรือฐานข้อมูลคดีจริง
- ระบบสิทธิ์ผู้ใช้งานและ Audit Log ฝั่ง production

ก่อนนำไปใช้งานจริงต้องเพิ่มการยืนยันตัวตน, RBAC, encryption, consent/legal basis, audit trail, data retention, API gateway, validation และการทดสอบความถูกต้องของกฎหมาย/ข้อมูล

## 5. สคริปต์วิดีโอนำเสนอแนะนำระบบ (ประมาณ 8–10 นาที)

### ฉากที่ 1: เปิดเรื่อง (0:00–0:45)

แสดงหน้า Home และพูดว่า:

> AI-BIP คือแพลตฟอร์มช่วยงานตำรวจที่รวมการคัดกรองภาคสนาม การเฝ้าระวังทะเบียนรถ การวิเคราะห์คดี และผู้ช่วยงานเฉพาะด้านไว้ใน workflow เดียว โดยทุกผลลัพธ์ยังต้องผ่านการตรวจสอบของเจ้าหน้าที่

### ฉากที่ 2: Field Check (0:45–2:30)

เลือก Face + Fingerprint, แสดงการสแกน, กดค้นหา, เปิด Candidate List และขยายภาพ

ประโยคสำคัญ:

> คะแนนความใกล้เคียงเป็นเพียงการจัดลำดับผล ไม่ใช่การยืนยันตัวบุคคล

จากนั้นสาธิต ID Card อย่างเดียวเพื่อให้เห็นว่าเป็นการตรวจ 1:1 และไม่แสดง similarity

### ฉากที่ 3: ANPR (2:30–4:00)

เปิดเฝ้าระวัง Real-time สลับภาพสดกับ Geofence จากนั้นเปิดทะเบียนเฝ้าระวัง เพิ่มทะเบียนรถหาย และเปิดตรวจข้อมูลกรมขนส่งเพื่อกรอก/ถ่ายภาพป้ายทะเบียน

### ฉากที่ 4: Fact Analyzer (4:00–6:30)

เลือกคดีลักทรัพย์ กดวิเคราะห์ แสดง progress และ Fact Matrix จากนั้นเปลี่ยนเป็นคดีฉ้อโกงคอมพิวเตอร์เพื่อให้เห็น Candidate Charges ที่เปลี่ยนตามคดี

### ฉากที่ 5: Legal Context (6:30–7:45)

เปิดแนวคำพิพากษา, Bail Risk และ Statute Reference ให้เห็นว่าผลลัพธ์เปลี่ยนตามคดีเดียวกัน

### ฉากที่ 6: สรุป (7:45–8:30)

แสดง Flow/Presentation Mode และปิดด้วยข้อความ:

> ระบบช่วยลดเวลาการค้นและจัดโครงสร้างข้อมูล แต่การยืนยันตัวบุคคล การตั้งข้อหา และการดำเนินการทางกฎหมายยังเป็นอำนาจและความรับผิดชอบของเจ้าหน้าที่ตามขั้นตอน

## 6. Checklist ก่อนบันทึกวิดีโอ

- ล้าง session state และเปิดหน้าเริ่มต้นใหม่
- ใช้ข้อมูลจำลองเท่านั้น
- ทดสอบทั้ง desktop และ mobile viewport
- ตรวจว่า progress animation ทำงานและผลเปลี่ยนตาม preset
- ตรวจว่า ANPR มี 3 แท็บหลักและ 2 แท็บย่อยเฉพาะ Real-time
- ตรวจ disclaimer ทุกจุด
- ปิด notification ส่วนตัวและข้อมูลจริงจากหน้าจอ
- บันทึกเสียงอธิบายว่าเป็น prototype ทุกครั้งที่แสดงผลลัพธ์ความเสี่ยง/ชีวมิติ

## 7. คำศัพท์สำหรับเอกสารและสไลด์

- Field Screening: การคัดกรองภาคสนาม
- Candidate: รายการบุคคล/ข้อมูลที่อาจสอดคล้อง
- Similarity: คะแนนความใกล้เคียงเพื่อจัดลำดับ
- Formal Verification: กระบวนการตรวจพิสูจน์ตามขั้นตอนหลัก
- Fact Matrix: ตารางองค์ประกอบข้อเท็จจริงที่พบและยังขาด
- Candidate Charges: ฐานความผิดที่ระบบเสนอให้พิจารณา
- Watchlist: รายการทะเบียนเฝ้าระวัง
- Geofence: พื้นที่ปิดล้อมและการสั่งการเชิงพื้นที่
